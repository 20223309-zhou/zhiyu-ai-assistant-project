# 【1】unstructured 需要 spaCy 英文模型 en_core_web_sm
#
#   为什么 pip 装不上：该模型不在 PyPI 分发，只在 GitHub Releases。
#   unstructured 首次解析文档时会自动去下载，国内访问 GitHub 基本失败：
#       RuntimeError: Failed to download spaCy model from https://github.com/...
#
#   解法（手动下载 wheel 后本地安装，绕过自动下载逻辑）：
#       # 直连不通就用 GitHub 加速镜像，下面几个哪个通用哪个
#       curl -L -o en_core_web_sm.whl https://gh-proxy.com/https://github.com/explosion/spacy-models/releases/download/en_core_web_sm-3.8.0/en_core_web_sm-3.8.0-py3-none-any.whl
#       pip install en_core_web_sm.whl
#
#   校验：sha256 应为 1932429db727d4bff3deed6b34cfc05df17794f4a52eeb26cf8928f7c1a0fb85
#         （自动下载路径自带校验，手动安装不会验，所以自己核一下）

# 【2】Windows 上 libmagic 会让 Python 进程直接崩 —— 不是抛异常，是段错误
#
#   现象：用到 unstructured 时进程无声退出，exit code 139，没有 traceback。
#   原因：magic/loader.py 有个候选路径列表，在 Windows 上会匹配到
#         Git for Windows 自带的 <Git>\usr\bin\msys-magic-1.dll。
#         那是 Cygwin 构建而非原生 Windows DLL，ctypes 加载时访问越权；
#         而 python-magic 只捕获 OSError / ImportError，接不住段错误。
#
#   解法：放一个原生 libmagic.dll，让候选列表更早命中它。
#     1. pip download python-magic-bin --no-deps -d <临时目录>
#     2. 从 wheel 里取出 magic/libmagic/libmagic.dll 和 magic.mgc
#     3. 两个文件都放进 venv 的 Scripts/ 目录（与 python.exe 同级）
#        —— 候选表里的 find_library('libmagic') 靠 PATH 命中，venv 激活时
#           Scripts 在 PATH 上，会先于第 11 位的 msys 库返回
#     4. 若某种启动方式 PATH 里没有 Scripts（例如直接调 .venv\Scripts\python.exe），
#        还需在 site-packages 放一个 .pth 文件把 Scripts 追加进 PATH

# 【3】Ollama 及本地模型
#
#   模型不走 pip 也不走 requirements，安装 Ollama 后要单独拉：
#       ollama pull qwen3-embedding:0.6b    # 嵌入，1024 维
#       ollama pull bge-m3                  # 嵌入备选，同为 1024 维
#
#   ⚠️ NVIDIA 驱动过旧时会报 CUDA error: device kernel image is invalid，
#      此时所有模型（包括对话模型）都无法加载。临时绕过：
#          setx OLLAMA_LLM_LIBRARY cpu      （设完必须重启 Ollama 才生效）
#      代价是对话模型推理变很慢（CPU 跑 4B 模型每句要几分钟），
#      但 embedding 够快，RAG 链路不受影响。根治要靠升级显卡驱动。
